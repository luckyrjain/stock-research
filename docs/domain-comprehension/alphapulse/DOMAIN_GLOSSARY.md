# Domain Glossary

| Term | Definition | Bounded context | Evidence |
|------|------------|-----------------|----------|
| **Verdict** (also "recommendation", "Signal Verdict", "Quant signal", "rating"/"pick") | The BUY/HOLD/SELL (3-tier, Stock Analysis) or BUY/WATCHLIST/HOLD/SELL (4-tier, Market Picks) call for a stock. **Disclosed inconsistency**: the same concept has at least four different names across the product's own UI — flagged in `docs/backlog.md`'s "Product & UX" section as a real vocabulary gap, not resolved. | Stock Analysis, Market Picks | docs/backlog.md:573-577 |
| **`degraded`** | Boolean field on a `Report` indicating the analyst's LLM call fell back to a hardcoded safe-HOLD response after both the primary and (if applicable) failover provider attempts failed. | Stock Analysis | backend/analyst/crew.py:658-693,925 (backend-core agent) |
| **`client_id`** | An anonymous per-browser UUID (`crypto.randomUUID()`), persisted in `localStorage` under key `alphapulse_client_id`. Explicitly documented as "a grouping key, not a security boundary" — non-secret, appears in plaintext query strings. | Watchlist & Positions, Portfolio Aggregator | frontend/lib/watchlist.ts:14,28-40 (frontend agent); backend/routes/watchlist.py:273-289 (P3b agent) |
| **Owner-resolved auth** | The identity-resolution rule (`resolve_owner()`): a valid session bearer token always wins over a supplied `client_id`; an invalid/expired token falls through to `client_id` rather than 401ing, since these endpoints don't require sign-in. | Watchlist & Positions, Portfolio Aggregator | backend/routes/watchlist.py:55-69 (P3b agent) |
| **Claim flow** | The opt-in, session-required action (`POST /api/watchlist/claim`, `POST /api/positions/claim`) that reassigns an anonymous browser's rows onto a signed-in account. Never automatic on sign-in. | Watchlist & Positions | frontend/app/auth/verify/page.tsx:68-93 (frontend agent, verified no auto-migration) |
| **Magic link** | A single-use, SHA-256-hashed, 15-minute-TTL sign-in token emailed to a user; the first successful click *is* account creation (no separate signup). | Accounts & Auth | backend/auth.py:68-101 (backend-core agent) |
| **Session** | A 30-day, SHA-256-hashed, opaque bearer token issued on magic-link verification. | Accounts & Auth | backend/auth.py:122-130 |
| **API key** | A long-lived, no-expiry, SHA-256-hashed credential for `/api/v1/*` programmatic access, tiered `free`/`pro` (100 vs. 1000 calls/hr) — no self-serve checkout exists; tier is set by an operator by hand. | Accounts & Auth | docs/PRD.md:258-265; backend/auth.py |
| **Golden cross / death cross** | EMA20 crossing above (golden) or below (death) EMA50 for an SME stock — the signal SME Signals screens for. | SME Signals | backend/pipelines/sme_ema_pipeline.py:129-146 (business-flow agent) |
| **Regime view** (SME Signals) | `GET /api/sme-signals?view=regime` — returns the latest stored row for every monitored stock (not filtered to only crossed stocks), using `DISTINCT ON (symbol) ORDER BY trade_date DESC`. | SME Signals | docs/api-reference.md:512-528 |
| **Consolidated view** | The read-only, no-new-fetch aggregation across Stock Analysis's `analysis` cache, Market Picks' cache, and SME's latest regime row for one symbol — `GET /api/consolidated/{symbol}`. Each section independently `null` is the *expected common case*, not an error. | Consolidated Search | docs/architecture.md:536-545; frontend/components/consolidated-card.tsx (frontend agent, verified null-handling) |
| **Watchlist alert** | A daily digest email (one per user per run, not per symbol) sent when a watched symbol's recommendation changes or moves ≥10% — sent only to account-owned (`user_id IS NOT NULL`) watchlist rows; anonymous `client_id` rows have no email and are excluded. | Watchlist & Positions | backend/pipelines/watchlist_alerts.py:118-135 (business-flow agent) |
| **Portfolio Aggregator** vs. **Portfolio** (`/portfolio`) | Two genuinely unrelated features sharing only the word "portfolio" and (partially) the `/api/portfolio` URL prefix by accident of routing. `Portfolio` (`positions` table) tracks Market Picks "I bought this" marks; `Portfolio Aggregator` (`profiles`→`accounts`→`assets`...) is a separate personal net-worth tracker. | Watchlist & Positions vs. Portfolio Aggregator | docs/database.md:238-240; docs/architecture.md:356-358 |
| **Profile** | A bare named picker under the Portfolio Aggregator (e.g. "Household member"), owned by `client_id`/`user_id` since migration `ec7850b73d2f`. **Not** the account system's own credentials — a `profiles` row has no login of its own. | Portfolio Aggregator | docs/database.md:609-621 |
| **Broker connection** | One row per `(account, broker)` pair, storing a plaintext `api_key` (treated as a public client id) and Fernet-encrypted `api_secret`/`access_token`. Two-stage lifecycle: credentials registered → OAuth/OTP handshake completed → `connected`. | Portfolio Aggregator | backend/db/models.py (backend-core agent); backend/routes/broker_sync.py (P3b agent) |
| **`adj_close`** | Split/bonus-adjusted closing price in `prices_daily`, written only by `corporate_actions_pipeline.py`'s recompute step; disclosed to currently have **zero production readers** (`portfolio_valuation` reads raw `close`). | EOD Price Store | docs/database.md:524-529 (Known schema gap #5); business-flow agent independently confirmed the raw-`close` read at `portfolio_valuation.py:99-106` |
| **`app_state`** | A generic `(namespace, key) → JSON` durable-state table replacing what used to be several per-feature JSON files under `output/` — the one place non-relational cross-run state (LLM cost totals, source health, market-picks daily snapshots, CAS import archives, CLI reports) is persisted. | Cross-cutting | backend/core/state_store.py:71-224 (backend-core agent) |
| **File cache** (`output/<SYMBOL>/<task>.json`) | TTL'd, regenerable, gitignored JSON cache — never a source of truth. Freshness always re-derived from `_meta.fetched_at`, never trusted from a store's own expiry mechanism. | Stock Analysis, Market Picks | backend/core/cache.py:43-172 (backend-core agent) |
| **"Never invent" convention** | The product-wide rule that a missing scraped/computed value is `null`, never a fabricated plausible-looking value (e.g. `change_pct` is `null`, never `0.0`, when there's no previous close). Cited repeatedly in `docs/PRD.md` §4 as a load-bearing product principle, and independently confirmed in code multiple times by this engagement's agents (e.g. `_is_failed_payload` in `core/cache.py`, `dcf_valuation.py`'s `None` returns). | Cross-cutting | docs/PRD.md:90; backend/core/cache.py:118-122 |
| **`resolve_symbol()`** | The securities-master symbol resolver (ISIN → exact code → fuzzy name → unresolved) used by `csv_import.py` and `hdfc_sync.py` to normalize a broker's raw code to a canonical NSE/BSE symbol. | Portfolio Aggregator / EOD Price Store | backend/tools/securities_master.py (quality/ops agent confirmed live call sites in csv_import.py:25,219, hdfc_sync.py:71,294) |
| **SSRF host-check** | The `_is_<host>_host()` pattern (`_is_nse_host`, `_is_trendlyne_host`) guarding any URL derived from scraped/parsed content (XBRL attachment URLs, Trendlyne redirect/search-result URLs) before it is fetched — applied specifically where a URL is attacker-influenceable, absent where every fetched URL is a hardcoded constant. | Stock Analysis (scrapers) | P3b + routes/pipelines agents, both independently confirmed |
